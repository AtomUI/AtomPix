# AtomPix Desktop UI 设计与设计图

> 文档状态：正式目标设计，设计图已同步，待 Desktop 按本基线迁移
>
> 基线时间：2026-08-24
>
> 适用范围：AtomPix Desktop Shell、首页、图片浏览器、四类处理面板、集成式批量反馈与设置页面

本文是当前 Desktop 视觉结构的权威入口。产品行为以 [MVP 范围](../product/mvp-scope.md) 为准，控件状态以 [Desktop 交互状态设计](../modules/desktop/interaction-state-design.md) 为准，AtomUI 组件边界以 [AtomUI 组件映射](../modules/desktop/atomui-component-mapping.md) 为准。

## 1. 设计目标

- 取消占据大量横向空间的宽文字侧栏，让首页和图片浏览器成为持续可见的主背景。
- 用贴左图标轨提供四大同级处理入口，不让导航视觉权重大于图片本身。
- 打开图片后先提供不带参数面板的完整浏览空间；用户明确选择工具后，再把内容区切换为 ImageGallery 与右侧处理面板并列的操作工作区。
- 浏览集合自然承担批量集合，消除独立批量页面与第二份选择列表。
- 保留图片浏览器的主图、导航、缩放工具栏和图片走廊；删除旧的常驻图片信息列，浏览态不为未知操作预留空白列。

### 1.1 AtomUI 视觉组件强制优先

“所有视觉 UI 组件尽量使用 AtomUI”是 Desktop 重构的强制选型约束，不是可选建议。“尽量”的确切含义是：每个可见、可交互组件都必须先核对 AtomUI 的公开稳定控件、公开组合方式、图标与 Theme Token；只有 AtomUI 没有匹配产品语义时，才允许退回 Avalonia 原生能力或 AtomPix 自定义控件。

- Button、IconButton、Tooltip、Dialog、Form、Select、Segmented、Slider、NumericUpDown、CheckBox、ColorPicker、ProgressBar、Spin、Alert、Result、ListView 和 ScrollViewer 等通用视觉能力，必须优先使用 AtomUI 公开组件。
- AtomPix 自定义 Control 只用于图片视口、CropCanvas、虚拟化画廊协调、缩略图任务状态 Presenter 等领域特有能力；自定义容器内部的通用按钮、表单和反馈仍使用 AtomUI。
- 任何偏离 AtomUI 的实现都必须在 [AtomUI 组件映射](../modules/desktop/atomui-component-mapping.md) 中记录缺失能力、不能直接使用的原因、采用的公开替代方案与验收方式。没有书面例外，不得自行绘制一套功能等价的通用控件。
- 所有颜色、圆角、间距、阴影、字体和 Motion 优先消费 AtomUI Token，并通过 AtomPix Theme Token 做稳定语义映射；不得在页面 AXAML 中散落重复常量或复制 AtomUI 私有模板。
- 继续禁止使用 `AtomUI.Desktop.Controls.DataGrid` 包。该禁令不因“AtomUI 优先”而解除；批量逐项展示使用画廊和主桌面包中的 `ListView`。

## 2. 品牌与图标资产

- `src/AtomPix.Desktop/Assets/Branding` 下现有 ICO 和各尺寸 PNG 全部保留并继续作为生产资产使用，不移动、不重绘、不生成第二套品牌设计。`ui-design/assets` 保存 `AtomPix-64.png` 与 `AtomPix-128.png` 的设计图专用同字节源副本；生成设计图时把所需 PNG 内嵌为 SVG `symbol`，不再留下跨目录或同目录外部引用。这些副本只服务文档，不进入 Desktop 生产资源。
- 图标轨顶部使用现有 AtomPix Logo；应用标题栏继续使用现有应用图标。
- 压缩、转换、Resize、Crop、设置继续使用 AtomUI Ant Design 公开图标 Provider。
- 图标轨不显示常驻文字。每个图标必须有 Tooltip、自动化名称和清晰选中/禁用状态，不能只靠颜色表达状态。

## 3. Shell 尺寸与层次

AtomPix 取消沉浸式标题栏。标题栏是独立、稳定的窗口层，Home、Browser、Crop 和批量状态都从标题栏下方的内容区开始布局，不允许图片或页面背景延伸到标题栏下层。标题栏使用稳定的浅色 Surface、主题默认前景色和一条低对比度底部分隔线；应用图标、标题、拖动区域及最小化/最大化/关闭按钮继续由 AtomUI 窗口能力承载，不再根据当前图片明暗切换渐变或前景色。

### 3.1 浏览态

```text
窗口运行时默认尺寸：1180 × 760 px
窗口最小尺寸： 960 × 640 px
右侧处理面板：不存在
```

内容区从标题栏下方开始。Home 使用完整内容区；打开图片或文件夹后，ImageGallery 占满内容区，不创建、不隐藏也不预留一个空白右列。图标轨悬浮在 Home 或 ImageGallery 上方并截断命中，但绝不进入标题栏。用户此时只表达了浏览意图，Shell 不默认选中任何处理工具。

### 3.2 操作态

```text
窗口运行时默认尺寸：1180 × 760 px
窗口最小尺寸： 960 × 640 px
右侧处理面板宽度：约 380 px
```

用户点击压缩、转换、Resize 或 Crop 后，标题栏下方内容区切换为两列：左列是可伸缩的 ImageGallery/裁剪工作区，右列是约 `380 px` 的处理面板。右侧面板参与普通布局，不使用 Drawer、Popup、遮罩、高 ZIndex 覆盖或从窗口边缘滑入的动画。顶层窗口保持 `1180 × 760 px` 默认尺寸和 `960 × 640 px` 最小尺寸；面板出现时只重新分配内容区宽度，窗口不得扩宽。

右侧面板从内容区顶部延伸到底部，使用不透明 Surface 和左侧弱分隔线；它不是浮动卡片，不保留原抽屉的上下空隙、圆角和投影。正文过长时只滚动面板正文，Header 与执行区按面板结构保持可见。ImageGallery 接收缩窄后的真实 Bounds，自行重新计算 Fit、工具栏与图片走廊的响应式布局；不得继续渲染一份被右侧面板遮挡的全宽主图。

切换其他工具时两列结构保持不变，只原位替换右侧内容。再次点击当前工具或使用面板关闭按钮后，`ActiveTool` 清空，右侧列从布局中移除，ImageGallery 恢复全宽浏览态。首轮不播放抽屉式位移或窗口扩展动画；布局变化必须在同一次 UI 提交中生效，避免先出现空白页或延迟一至两秒才显示面板。

### 3.3 图标轨

- 约 `50 px` 宽，左边紧贴窗口内容边界；轨道使用与图片画廊相同的约 `94%` 不透明白色浮层 Token，不绘制边框。左上角与左下角保持直角，只在右上角和右下角使用圆角，并通过统一 Theme Token 提供轻量投影。
- 图标轨高度只包裹图标、图标间距和上下内边距，不得上顶窗口或下贴窗口底部；整个轨道在窗口可用区域内垂直居中，并避开标题栏按钮命中区。
- 从上到下依次为：Logo、压缩体积、转换格式、调整尺寸（Resize）、剪裁尺寸（Crop）、设置。该顺序在 Home、Browser 和处理态之间必须一致。
- Logo 与操作图标使用不带边框的透明按钮；操作图标基准尺寸为 `22 × 22 DIP`，Logo 视觉尺寸为 `28 × 28 DIP`。默认、鼠标悬停和按下状态都不得改变按钮背景、边框或前景色，只有明确的当前工具选中态由轨道底层选中指示负责表达。
- Logo 与处理操作之间只保留一条弱分组线；设置与上方操作按钮之间不绘制额外分割线。
- Logo 是返回首页动作。再次点击当前工具图标关闭右侧处理面板并回到浏览态；点击其他工具图标时两列结构保持不变，只原位切换面板内容。
- 运行正式任务时图标轨整体锁定，只保留当前面板的查看进度和取消。

## 4. 首页

- 首页采用“轻品牌启动台”构图：浅灰工作区保留极低透明度的品牌红/AtomUI 蓝环境光，标题、说明、拖放区与入口形成紧凑的中央布局。外层只负责布局，不绘制白色卡片、实线边界或投影；虚线框外直接显示工作区渐变背景。
- 保留标题、标题下方的一行简短操作说明、拖放区、“打开图片”和“打开文件夹”；中央使用现有 AtomPix Logo 与柔和圆形底衬作为唯一主视觉，不再使用通用图片上传插画。删除额外来源说明、格式/静态帧说明以及底部四张快捷操作卡。
- “打开图片”使用多选图片选择器；“打开文件夹”仍使用单目录选择器。
- 启动台布局在默认窗口下最大宽度 `920 px`、高度 `520 px`，在最小窗口下水平自适应收窄；标题、说明与内部拖放区属于同一个居中构图。内部拖放区占据剩余空间，使用轻量中性底色、`18 px` 圆角和克制虚线边界。中央 `64 DIP` Logo 使用至少 `128 × 128 px` 的现有品牌位图作为高 DPI 图源。错误反馈覆盖在启动台顶部而不改变启动台的中心位置。
- 无图片时点击图标轨四大工具同样先打开多选图片选择器；选择成功后进入浏览器并自动展开目标面板，取消保持首页。

## 5. 图片浏览器与处理集合

- 首页“打开图片”或“打开文件夹”正常打开来源后，首先进入四大工具均未选中的纯 Browser；ImageGallery 使用标题栏下方的完整内容区，右侧处理面板不存在。只有用户点击图标轨工具，或者从首页无图片状态点击某个工具并完成选图时，才进入对应操作态。
- 浏览态主图视口覆盖 ImageGallery 自己的全部 Bounds，但不进入独立标题栏。图片内容默认按 `Contain / Uniform` 保持比例、居中并完整显示全部边缘，比例不一致时允许左右或上下显示白色留白。不再保留右侧图片信息列、底部实色画廊占位区或任何旧操作面板。图标轨悬浮在 ImageGallery 上方并截断命中，点击不能穿透到主图导航区。
- Browser 图标轨必须与 Home 使用完全相同的宽度、高度、垂直位置、Logo、圆角、阴影、图标顺序、间距和透明默认按钮背景；仅当前工具选中态增加淡蓝背景与品牌色图标。
- Browser 主图与走廊缩略图统一使用用户从 `D:\111` 提供并复制到 `assets/` 的 JPG 摄影素材。每张 SVG 只把自己实际使用的照片各内嵌一次，再通过内部 `symbol/use` 复用；交付后的 SVG 不依赖 `D:\111`、`assets/` 或任何其他外部图片路径。
- 主图不再常驻显示上一张/下一张箭头容器。普通浏览模式在视口左右各提供约 `64–80 px` 的透明边缘点击区：短距离单击切换相邻图片，拖动不触发；第一张的左区和最后一张的右区禁用，不循环跳转。
- 顶部缩放工具栏继续浮在主图上并优先接收输入；Crop 模式完全关闭主图边缘点击换图。左右透明热区必须从命中路径中失效（等价于 `IsHitTestVisible=false`），不能只把视觉隐藏后继续截获 Pointer；CropCanvas 独占其工作区内的拖动、控制点和选区输入。
- 图片走廊最左侧固定增加纯图标“追加图片”按钮，不显示常驻文字，但必须保留 Tooltip、自动化名称和可访问语义。它不是图片项、不能成为 CurrentItem，只打开多选图片选择器。该按钮与上一张/下一张按钮、图标轨按钮共享同一个 AtomPix 公共 AtomUI Button Style：无边框、透明背景，默认/悬停/按下均不改变背景、边框或前景色。
- 图片走廊采用固定控制区：`追加图片 | 上一张 | 横向滚动缩略图 | 下一张`。追加图片和两个导航按钮都不进入滚动内容；左侧“上一张”固定在追加图片右侧，右侧“下一张”固定在走廊最右侧。
- 图片走廊是 ImageGallery 内部浮在主图上的底部画廊 Dock，不参与 Shell 列布局，也不绘制贯穿窗口的白色底栏。画廊相对 ImageGallery Bounds 左右各留 `20 px`，最大宽度 `900 px` 并在左侧工作区内水平居中；总高度 `68 px`，距底部 `8 px`，四角统一为 `12 px` 圆角。表面与图标轨共享约 `94%` 不透明度的白色浮层 Token 和轻投影，不依赖跨平台背景模糊。
- 进入操作态后，ImageGallery 随左列变窄，画廊按照组件新的 Bounds 自适应收窄并保持居中；固定控制区保持尺寸，缩略图视口自适应，并把 CurrentItem 保持在可见范围。画廊无需感知或避让右侧面板，也不得使用窗口绝对坐标推算位置。
- 浮动画廊外框高 `68 px`，使用 `2 px` 等值内边距，内部内容组高 `64 px` 并整体垂直居中。缩略图基准尺寸为 `84 × 56 DIP`；三个固定控制列各宽 `52 px`，按钮使用 AtomUI `Large` 密度得到稳定的 `40 px` 高度，图标为 `22 × 22 DIP`。缩略图下方保留滚动块空间；所有图标、箭头和缩略图按同一中心线对齐。缩略图彼此零间隙，当前项使用淡白蒙版和底部 `3 px` 品牌色指示条，滚动轨道保持透明。
- 主图边缘点击、走廊上一张/下一张和缩略图点击共享同一个 CurrentItem 导航命令。切换成功后当前缩略图必须自动滚入可见范围；两个走廊按钮在首尾项、Loading 或任务锁定时显示真实禁用态。
- 新图片追加到集合末尾；重复、不支持和不可读取项按原因反馈。走廊不提供追加文件夹。
- 当前高亮项只决定主图与单张处理目标；走廊全部图片是压缩、转换、Resize 的批量范围。切换高亮项后，当前工具只在新图片读取完成时同步单张目标；Resize 保留正在编辑的尺寸参数。

### 5.1 Browser 与 Crop 的图片呈现模式

- 普通 Browser 默认使用 `Fit / Contain / Uniform`：当前图片以 ImageGallery 主图视口为边界保持宽高比并完整显示，不做视觉裁切；横向比例不足时左右留白，纵向比例不足时上下留白。窗口尺寸或左右列状态变化后，立即按新的左列视口重新适配。
- 打开 Crop 后，左侧从普通 Browser 主图切换为浅色 Crop 工作台，右侧显示 Crop 参数面板。前景 `AtomPixCropCanvas` 在排除贴左图标轨和底部浮动画廊后的安全工作区内用 `Contain / Uniform` 完整展示自动方向校正后的原图，所有边缘和八个控制点必须可达；右侧面板已经位于独立布局列，不参与 CropCanvas 的遮挡排除计算。
- Crop 工作台统一使用 Home 的浅灰 Surface（当前为 `#F5F7FA`）。图片增加克制的浅灰边界以区分白色图片；深色遮罩只允许绘制在原图内部、裁剪选区之外，禁止再把整个 CropCanvas 填充为深色。第一阶段不使用背景模糊，也不为了背景效果重复解码。
- Desktop 维护唯一的 Crop SafeArea 布局事实：导航轨宽度、画廊高度和画廊边缘间距使用共享 AtomPix Layout Token，CropCanvas 使用由这些 Token 推导的安全 Margin。Avalonia 在窗口、DPI、左列宽度或右侧面板状态变化时通过正常 `Measure / Arrange` 实时分配可用 Bounds，CropCanvas 只在自己的 Bounds 内重新计算 `Contain`；禁止定时器、窗口绝对坐标、手写 Width/Height 和各组件各自维护一套避让常量。若未来画廊高度支持运行时任意变化，再由 ImageGallery 公开实际 Bounds 驱动 SafeArea，不读取其私有模板部件。
- Crop 选框、外部遮罩和八个控制点只属于前景完整原图。最终提交必须由前景视口变换换算为自动方向校正后原图的像素 `CropRectangle`；全屏背景、窗口坐标和截图均不得进入 Core/Workflow 请求。
- Crop 模式只允许通过浮动画廊的固定上一张、固定下一张和缩略图切换 CurrentItem。切图保留比例意图，为新图片建立新的最大合法选区，不复用旧图绝对像素坐标；关闭 Crop 面板后恢复全宽 Browser Fit 呈现，同一会话内的合法 Crop 草稿按既定规则保留。
- 浏览器继续没有搜索框。更换文件夹来源时点击 Logo 返回首页。

## 6. 四类处理面板

所有右侧处理面板采用统一结构：

```text
Header：工具名称、当前集合摘要、关闭按钮；工具身份同时由左侧 Active 图标表达
Body：参数 Card、输出设置、校验/错误、结果或进度；独立滚动
Footer：单张处理；满足条件时显示批量处理
```

- 集合只有一张时隐藏批量按钮。
- 集合至少两张时，压缩、转换和 Resize 同时显示“单张处理”与“批量处理”；批量固定作用于走廊全部图片，按钮文案不附带数量。
- Crop 永远只显示“开始剪裁”。Crop 打开后，左列从 Browser Fit 切换为“浅灰背景 + 前景完整原图 CropCanvas”，浮动画廊不消失；初次进入时必须把 Browser 当前项（打开文件夹默认第一张）同步为 Gallery 当前选择并立即展示，不能要求用户再次点击缩略图。右列显示 Crop 参数，主图左右边缘热区完全停止命中，切换图片只能使用画廊并重建合法选区。
- 工具切换时各自草稿在当前浏览会话内保留。关闭面板不清空草稿；返回首页结束会话并释放草稿。

## 7. 批量运行与终态

- 点击批量开始时冻结走廊顺序、共享参数和输出计划，之后禁止追加、移出、切换当前图片或切换工具。
- 右侧始终保留当前工具的同一个配置 View，不跳转、不替换内容，也不出现“返回单张配置”。运行期间参数区原位只读，Footer 切换为总体进度、完成数量、成功/失败/跳过计数和取消动作。
- 终态后 Footer 恢复“单张处理 / 批量处理”。单张结果由窗口顶部中央 Message 呈现；批量结果由窗口右上角 Notification 呈现，点击后打开居中的结果详情 Dialog。
- 批量全部成功 Notification 6 秒自动关闭；部分成功、失败、跳过或取消保持到用户关闭。关闭通知或详情 Dialog 不改变当前图片、草稿或磁盘输出。
- 详情 Dialog 使用普通滚动列表展示逐项状态和安全原因，禁止使用 DataGrid；恢复动作只建立新的 Ready 草稿，不自动执行。
- **TODO（后期迭代）**：缩略图同步显示 Pending、Running、Succeeded、Failed、Skipped 或 Canceled 标记；当前版本由右侧面板表达批量进度、当前处理项和终态。
- Workflow 返回最终 `BatchResult` 后校正右侧面板摘要与结果明细；缩略图状态校正随第 7.2 节后期能力一并实现。
- 重试失败项或处理未完成项会用目标子集建立新的走廊和 Ready 草稿；旧结果保持只读，不复活旧 BatchJob。

### 7.1 批量活动项自动跟随动画（TODO，后期迭代）

本节与缩略图任务状态系统一并后置，不属于当前 ImageGallery 迁移和 Desktop 重构的施工/验收范围。当前批量任务不派生供画廊消费的 `ActiveBatchIndex`，也不因 Running 项变化自动抢夺走廊滚动位置；画廊继续只跟随用户选择的 `CurrentItem`，右侧处理面板负责显示当前处理项。以下规则保留为未来获得正式公开 Follow/Bring-Into-View API 后的目标设计。

- 画廊同时维护两个不同语义：`CurrentItem` 是批量开始前冻结的主图预览/单张处理目标，`ActiveBatchIndex` 是当前正在处理的批量项目。批量推进只更新后者，不切换主图、不改变当前项淡白蒙版，也不触发新的主图解码。
- 每当一条经过代次、BatchId、Sequence、Index 和 InputPath 校验的进度消息把某项置为 `Running`，画廊先立即显示该项的处理中标记，再在下一次有效布局后检查其缩略图是否完整可见。Pending 或终态消息本身不触发追踪滚动。
- 若活动项已经完整位于缩略图视口内，滚动偏移保持不变；若被左/右边界部分遮挡或完全不可见，只滚动能够让它完整进入视口的最短距离。递增批量通常表现为缩略图内容平滑向左移动，新活动项从被裁切的右侧进入并停在最右侧完整可见槽位；反向目标采用对称方向。
- 以“视口显示 6 张、开始第 7 张”为基准场景：前 6 张处理期间画廊不移动；第 7 张进入 Running 时，滚动内容向左平移一个缩略图槽位，第 7 张从右侧露出并完整落位。追加图片、上一张和下一张三个固定控制不参与动画，画廊外框、主图和右侧处理面板也不移动。
- 默认单次跟随使用 `200 ms`、无回弹的 Ease-out 动画；短距离仍使用同一时长，跨越多个槽位时最多放宽到 `280 ms`，不得逐项排队播放或产生弹簧、缩放、闪烁效果。使用 AtomPix Motion Token 映射 AtomUI/Avalonia 的公开动效能力，不复制或修改 AtomUI 私有模板。
- 动画未完成又收到更新的合法 Running 项时，取消旧目标并从当前视觉偏移平滑改投最新目标；多个 UI 回调在同一帧内合并为一次定位。不得积压“逐张追赶”动画，也不得让快速图片处理被 UI 动画反向阻塞。
- 鼠标滚轮、触控板或拖动滚动条属于用户直接滚动，手势期间优先于自动跟随；手势结束后进入 `1200 ms` 暂停期。暂停期内只更新状态，不抢夺偏移；暂停结束时若最新活动项仍不可见，只执行一次指向最新项目的合并动画。新的批量任务或恢复任务开始时自动恢复跟随。
- 用户启用系统减少动态效果，或 AtomPix 全局动效被关闭时，仍执行“活动项完整可见”的定位，但偏移立即更新，不播放过渡。窗口、DPI 或左右列状态变化只在新布局稳定后重新计算目标，不能使用设计图中的固定屏幕坐标。
- 任务自然结束、失败或取消时停止自动跟随并保留最后视觉偏移，便于查看相邻结果；用户执行“继续编辑/处理”返回 Ready 后，再按普通导航规则把 `CurrentItem` 滚入可见范围。最终 `BatchResult` 校正状态时不重复播放画廊动画。

### 7.2 缩略图右上角任务状态系统（TODO，后期迭代）

本节保留后期目标设计，但不属于当前 ImageGallery 迁移和 Desktop 重构的施工/验收范围。当前批量状态、总体进度、当前处理项与最终结果统一在右侧面板表达；设计图中已经绘制的缩略图徽标只用于记录未来方向，不能据此要求当前版本访问 ImageGallery internal 缩略图容器或复制其模板。

后期实现时，批量状态使用覆盖在每张缩略图右上角的统一 `Gallery Processing Status Indicator`。它不是按钮、不占缩略图布局尺寸，也不改变图片裁切区域。批量提交快照建立后，批次内全部项目立即获得同一位置的状态槽；普通浏览、单张处理和未进入执行快照的图片不显示状态槽。StartRejected 返回 Ready 时清除本次临时 Pending 槽，已经进入终态的旧批次则保留到用户创建新草稿或结束浏览会话。

状态槽使用以下固定视觉参数，单位均为 Avalonia DIP：

| Token | 默认值 | 规则 |
| --- | ---: | --- |
| `GalleryStatusIndicatorSize` | `20` | 圆形外框直径；不随缩略图缩放。 |
| `GalleryStatusIndicatorInsetTop` | `2` | 距缩略图可视上边缘。 |
| `GalleryStatusIndicatorInsetRight` | `2` | 距缩略图可视右边缘。 |
| `GalleryStatusIndicatorKeyline` | `2` | 白色外描边，保证在亮暗图片上都可识别。 |
| `GalleryStatusGlyphSize` | `12` | 中央语义图形的设计包围盒。 |
| `GalleryStatusGlyphStroke` | `2` | 对勾、叉号、时钟、感叹号和横线的基准线宽。 |

状态映射冻结如下；颜色必须来自 AtomPix 语义 Token，不允许页面自行写另一套颜色：

| 状态 | 背景默认值 | 白色图形 | 动态行为 | Tooltip / 自动化语义 |
| --- | --- | --- | --- | --- |
| `Pending` | `#AEB7C2` | 小时钟 | 静止 | 等待处理 |
| `Running` | `#1677FF` | `220°` 开口圆弧 | 顺时针连续旋转 | 正在处理；单项进度不可用 |
| `Succeeded` | `#52C41A` | 对勾 | 静止 | 处理成功 |
| `Failed` | `#FF4D4F` | 叉号 | 静止 | 处理失败；Tooltip 可追加脱敏原因 |
| `Skipped` | `#FAAD14` | 感叹号 | 静止 | 已跳过；Tooltip 可追加脱敏原因 |
| `Canceled` | `#8C8C8C` | 水平短线 | 静止 | 已取消 |

- 状态图形和文字语义必须同时存在，颜色不能成为唯一信息。Pending 使用时钟而不是无含义的灰色空点；Canceled 使用横线，与 Failed 的叉号和 Skipped 的感叹号明确区分。
- `Running` 旋转周期为 `800 ms`、线性、顺时针、无限循环；它只表达不确定等待，不表示图片内部百分比。动画从合法 Running 状态提交到 UI 时开始，进入任何终态或容器离开视觉树时立即停止。
- 状态替换使用 `120 ms` Ease-out 透明度交叉淡化；不使用弹跳、闪烁或庆祝动画。Running 和终态若在同一 UI 帧抵达，以最新合法 Sequence 的终态为准，可以直接显示终态，不人为延迟结果以展示一次 Spinner。
- 系统 Reduced Motion 或 AtomPix 全局动效关闭时，旋转和交叉淡化都禁用，状态图形立即替换；状态信息与颜色不变。
- Z 轴从低到高固定为：缩略图图片、CurrentItem 淡白蒙版、CurrentItem 底部品牌色指示条、任务状态槽。白色描边和状态图形不得被选中蒙版降低对比度；状态槽随所属缩略图一起参与第 7.1 节的真实滚动，不能固定在画廊视口上。
- 状态槽本身不接收点击、不改变 CurrentItem，也不建立独立焦点。Tooltip 与 `AutomationProperties.Name` 由缩略图容器承载，例如“第 7 项，森林晨雾.png，正在处理”；批量总体进度使用右侧面板的节流 LiveRegion，不让每个缩略图状态变化连续抢占屏幕阅读器播报。
- 虚拟化状态必须绑定冻结的 Batch Index 与单项投影，不绑定容器序号。容器回收或重新附着时先清除旧图标、Tooltip、伪类和动画时钟，再投影新项目；同一时刻只允许真实 Running 项的已实现容器执行旋转动画。
- Pending 可以直接进入 Failed、Skipped 或 Canceled，不得为了视觉连续性伪造 Running。最终 `BatchResult` 只校正不一致状态；相同终态不重复淡化，校正也不触发画廊滚动。

- 设置图标把 Shell 主工作区切换为普通设置页面，不使用 Dialog、遮罩或 Overlay 动画；进入设置时暂时隐藏全局图标轨和右侧图片处理面板，返回后恢复进入前的 Home/Browser、ActiveTool 与工具草稿。

- 设置采用桌面偏好页布局：左侧为浅灰色分区栏，右侧为宽松的双列属性行；默认压缩、默认转换、默认输出用标题、说明、控件和弱分隔线组织，不再堆叠 Card。
- Footer 始终固定。默认配置页左侧显示“恢复默认”，右侧显示“取消 / 保存设置”；关于页隐藏“恢复默认”。关闭按钮、Escape 与“取消”均静默放弃未保存草稿，不再弹出二次确认。
- 保存成功后设置页面保持打开，并由主窗口顶部中央的 AtomUI Message 反馈；保存失败同样保持页面与草稿。关于分区采用左对齐品牌信息与键值信息行，不使用居中的运行环境 Card。
- 打开和关闭设置不清空 ActiveTool、图片集合或工具草稿；新默认值只影响以后新建的草稿。

## 10. 设计图表现约束

### 10.1 四大处理面板的 Inspector 视觉基线

- 压缩、转换、Resize 与 Crop 的右侧面板统一采用轻量专业 Inspector：一个连续的浅色 Surface，通过留白、弱分隔线和字体层级组织内容，不再使用多层大 Card 套 Card。
- Header 固定为“工具名称 + 单张/数量 Tag + 关闭按钮 + 当前文件上下文”；文件名与尺寸是弱化的上下文信息，不与工具名称争夺主层级。
- Body 只强调当前工具的首要决策：压缩模式、输出格式、Resize 调整方式或 Crop 比例；次级字段沿统一垂直网格排列，并按当前选择渐进显示。
- 永久安全规则使用低强调说明“AtomPix 不会覆盖原始图片”；只有实际校验失败或路径冲突才使用 Warning/Error Alert，禁止让常驻大面积黄色警告抢占主视觉。
- Footer 固定在面板底部，以接近全宽的 Primary Button 形成视觉收尾；压缩、转换和 Resize 的批量入口作为较弱的次级动作，Crop 永远只保留单张动作。
- 上述视觉应优先由 AtomUI `Segmented`、`CheckBox`、`TextBox`、`Select`、`Button`、`Slider` 与文本/Alert 公开能力实现；颜色、圆角、间距和分隔线映射到 AtomUI/AtomPix Theme Token。

- SVG 使用当前 AtomUI 浅色风格的近似颜色帮助人肉判断；生产实现必须映射到 AtomUI/AtomPix 语义 Token，不能照抄散落色值。
- SVG 设计图中的标题栏 ICO、图标轨 Logo 和演示照片必须以 `data:` 资源内嵌于当前 SVG；同一二进制素材在单个文件内只定义一次，并通过 `symbol/use` 复用。`assets/atompix-brand-64.png` / `assets/atompix-brand-128.png` 是生产品牌 PNG 的设计图源副本，不得重新绘制或修改其内容。交付验收必须把 SVG 单独复制到不含 `assets` 的目录后实际渲染，禁止用“在仓库原位置能打开”替代独立文件破图检查。
- 设计图中的自然摄影图片来自 `assets/` 的设计专用素材，不是 Desktop 生产图片资产。
- 设计图只冻结信息层级、窗口关系和首轮尺寸，不冻结最终字形渲染、平台标题栏细节或阴影算法。
- 设计图中所有可见处理入口均对应本文和交互状态文档；不得为了画面完整增加预设、批量 Crop、处理后效果预测、体积估算或其他未进入当前范围的入口。
